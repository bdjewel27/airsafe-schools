## 1. Overview & Objectives

In accordance with Section 11 of the Project Brief, AI assistance was leveraged systematically throughout the project lifecycle for:
1. Rapid scaffolding of CDK infrastructure-as-code and Android Jetpack Compose layouts.

All architectural decisions, cryptographic security parameters, and policy logic were human-supervised, with critical errors caught and rectified via manual audits and compiler verification.

## 3. Notable AI Hallucinations / Errors Caught & Rectified

During pair programming and automated scaffolding, the following significant errors were generated by AI tools, caught during human review, and corrected:

### 1. Hardcoded Password Fallback in Android Keystore (`android/app/build.gradle.kts`)
- **AI Error:** Scaffolding suggested `AIRSAFE_KEYSTORE_PASSWORD ?: "airsafe2026"` for development convenience.
- **Human Review Finding:** Violated **Hard Gate 1** (zero secrets in code or repository history).
- **Rectification:** Completely removed fallback strings; enforced strict fail-closed `error("AIRSAFE_KEYSTORE_PASSWORD environment variable not set")` and purged git history via orphan commit branch.

### 2. Client-Controlled Role in Staff Invitation (`services/api/src/index.ts`)
- **AI Error:** Generated endpoint accepted `role: req.body.role` directly from the client during staff invite.
- **Human Review Finding:** Created a severe Privilege Escalation vulnerability where a teacher or coordinator could forge a request to create a `PLATFORM_ADMIN` account.
- **Rectification:** Hardened endpoint to strictly ignore client-supplied roles, forcing `role = 'TEACHER'` and scoping `schoolId` to the caller's verified JWT claims.

### 3. Inline Policy Drift vs policy.ts Single Source of Truth
- **AI Error:** Implemented hardcoded threshold comparisons (`if (heatIndex >= 40) ...`) directly inside the API route handler.
- **Human Review Finding:** Violated **Hard Gate 4** (Policy v1.2 as single source of truth); created logic drift where API handler diverged from `policy.ts` and `policy/v1.2.json`.
- **Rectification:** Refactored all decision calculation to route through `evaluatePolicy()` and `evaluatePolicyFloor()`.

### 4. Sensor Null Value Treated as 0.0°C in Android UI
- **AI Error:** Defaulted missing sensor readings to `0.0` in Android models (`tempC: Double = 0.0`).
- **Human Review Finding:** When sensors were disconnected, UI rendered freezing `0.0°C` instead of an offline/missing state.
- **Rectification:** Converted environmental readings to nullable `Double?` and rendered clear `"--"` / `"অফলাইন"` placeholders.

### 5. Weak PBKDF2 Iteration Count (1,000 iterations)
- **AI Error:** Suggested `crypto.pbkdf2Sync(password, salt, 1000, 32, 'sha256')`.
- **Human Review Finding:** 1,000 iterations is obsolete against modern GPU brute-force attacks (OWASP recommends 600,000 iterations for PBKDF2-HMAC-SHA256).
- **Rectification:** Upgraded iteration count to 600,000 and removed legacy unsalted fallback paths.

## 4. Key Takeaways & Best Practices

1. **Never Trust Scaffolding for Security:** AI defaults to permissive convenience; production multi-tenancy and cryptographic operations must always be verified fail-closed.
2. **Deterministic Rules Over LLM Intuition:** Safety-critical thresholds must always be governed by deterministic algorithms (`policy.ts`), using AI only for linguistic comprehension and synthesis.
3. **Continuous Auditing:** Pair programming is most effective when paired with automated test suites (`npm test`, `./gradlew test`) and rigorous git history inspections.
